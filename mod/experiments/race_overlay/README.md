# Расовый overlay двух рукавов

Эксперимент добавляет игровую идентичность поверх пяти штатных слотов движка. Он
не создаёт шестой `TRace` и не меняет расовые таблицы ядра.

| слот движка | Старый рукав | Второй Дом |
|---:|---|---|
| 0 | Малок | Стронг |
| 1 | Пеленг | Агилл |
| 2 | Человек | Медиум |
| 3 | Фэянин | Интелл |
| 4 | Гаалец | Мензол |

## Что делает

- `CE_RaceIdentity` — сохранённая кастомная инфошка на корабле игрока. В ней
  `Data1` — происхождение, `Data2` — текущая идентичность, `Data3=1` — версия
  схемы.
- `Ctrl+R` на пиратской базе открывает выбор пяти рас **текущего** рукава. После
  подтверждения вызывает подтверждённые функции `ShipPilotRace` и `ShipFace`.
- При переходе в другой рукав слой сохраняет слот, лицо, происхождение и текущую
  идентичность в свободных ячейках переходного stash `17..22`, затем восстанавливает
  их у нового капитана.

Поэтому фэянин из старого рукава может остаться фэянином во Втором Доме, хотя
местный слот `3` называется Интеллом.

## Основания в коде

- В актуальном Redux есть функция смены подданства на ПБ, вызывающая
  `ShipPilotRace(Player(), s)` и `ShipFace(Player(), f)`.
- Функция `ShipCustomFaction` не подходит: она прямо отклоняет присвоение игроку.
- `ShipAddCustomShipInfo` и `ShipCustomShipInfoData/TextData` сохраняют до трёх
  числовых и трёх текстовых значений на корабле игрока.
- Ветка команды уже использует `CEAdapterGalaxyIsSecondHome` и перенос игрока
  через `CEAdapterStashPlayerValue`/`CEAdapterFetchPlayerValue`.

Пин исходников команды и их SHA-256 лежат в `upstream.json`. Скрипт подготовки
откажется работать, если хотя бы один из этих файлов изменился.

## Подготовка тестовой копии

```bash
python mod/tools/prepare_race_overlay.py \
  --team /path/to/System-tex-deti_eltan \
  --output /path/to/NEW-overlay-source
```

Скрипт создаёт только новую исходную папку. Он не меняет checkout команды, игру
или `dist/`. Для получения игрового модуля нужно собрать полученные RSON и
BlockPar-файлы штатным pipeline команды, затем вручную пройти тест.

## Обязательный ручной тест

1. На чистом сохранении открыть пиратскую базу и нажать `Ctrl+R`.
2. Выбрать расу текущего рукава; проверить портрет и описание `Происхождение`.
3. Сохраниться, перезагрузиться, повторно проверить описание.
4. Активировать Якорь Двух Домов и перейти во Второй Дом.
5. Проверить, что происхождение и текущая идентичность не заменились локальным
   названием слота; вернуться и повторить шаг 3.
6. Проверить отказ перехода при повреждённых либо отсутствующих данных личности.

До этого ручного запуска результат имеет статус `source-overlay-only`.
